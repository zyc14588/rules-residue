# M1 / 平台现行合同与 R2 游戏包设计冲突登记

本文件不是否决 R2，而是阻止施工者在未评估宿主能力时静默覆盖平台或游戏合同。

## 冲突处理原则

每一项必须归类为：

- `PACKAGE_DECLARABLE`：现行平台已允许由包声明；
- `PLATFORM_CAPABILITY_PROBE`：需要M2技术探针确认；
- `PLATFORM_CHANGE_PROPOSAL`：平台缺能力时另行提交正式变更；
- `R2_COMPATIBILITY_ADAPTER`：可在游戏包内通过兼容层实现；
- `BLOCKED_DESIGN_CONFLICT`：两套已冻结权威无法同时成立，需项目所有者裁决。

不得在 R2 游戏仓库内硬编码平台后门。

## 冲突表

| ID | R2要求 | 已知宿主风险 | M2处理 |
|---|---|---|---|
| `R2-INT-001` | 标准4人，正式支持2—6人 | 历史平台官方TRPG席位曾以1—4名玩家为基线 | 检查游戏包席位声明Schema与服务器上限；若上限硬编码4，提交平台变更提案，不得缩减R2至4人 |
| `R2-INT-002` | 死者持续使用亡者视角并有限行动 | 历史通用死亡契约偏向只读旁观/安全阶段替代角色 | 证明包可声明亡者角色视图、动作白名单和因果系绳；否则提交能力扩展 |
| `R2-INT-003` | 终局不可逆动作不弹系统确认 | 平台历史默认重大后果确认；自然语言高影响行动也可能要求确认 | 设计“世界内多步骤动作契约 + 最终明确意图”适配；只取消末端UI二次确认，不得允许含糊语句误触发 |
| `R2-INT-004` | 因果公平但不保证明显独立信号 | 平台历史重大后果可能要求明确风险信号 | 区分平台通用安全/合法性提示与游戏内谜题信号；逻辑完全异常区和战役终止操作仍必须明显警告 |
| `R2-INT-005` | 35—60小时常规、最高约100小时 | 历史官方首发内容可能以较短单次/短战役为基线 | 确认Campaign、存档、版本锁与内容包规模支持长期战役；M2不承诺一次实现六区全部内容 |
| `R2-INT-006` | 真结局存档解锁高资源新开局 | 运行中版本锁、存档迁移与跨战役状态必须严格受控 | 将其设计为账号/谱系级解锁声明，不继承上一战役权威规则状态 |
| `R2-INT-007` | 全部六区观测才有真结局资格 | M2垂直切片只含一个大区 | M2使用六区接口模拟和一个真实区实现；不得声称已验收完整发布内容 |
| `R2-INT-008` | 角色1死亡立即灭世且禁止普通撤销 | 通用纠正/恢复/分支机制可能允许操作回退 | 将“灭世阈值接受”建模为战役终止事件；M2只做候选游戏包模拟，不修改平台全局历史语义 |
| `R2-INT-009` | 玩家外部笔记/记忆不可被游戏抹除 | AI与上下文系统可能错误地把玩家记忆当作角色权威事实 | 明确玩家记忆主张、世界内证据、Agent Memory和权威状态四层隔离 |
| `R2-INT-010` | 所有正式装备都是规则 | M1现有装备/物品Schema可能是通用对象 | 使用R2扩展Schema或包命名空间，不破坏平台通用物品模型 |
| `R2-INT-011` | 每次检查均重新执行绝对红线过滤 | 现行流水线可能只在生成或发布时检查 | M2先实现包侧可重复过滤门禁与证据；平台运行时过滤能力不足时提交独立变更 |
| `R2-INT-012` | 逻辑完全异常区允许真正逻辑冲突 | 通用规则引擎通常要求确定性 | 机械层仍必须确定性地描述“冲突如何被执行”；表现为逻辑异常不等于引擎随机改答案 |

## 结论门禁

只有当每项冲突都得到以下之一时，R2安装批次才可进入最终 ACCEPT：

```text
RESOLVED_PACKAGE_DECLARATION
RESOLVED_ADAPTER
DEFERRED_WITH_NON_BLOCKING_PROOF
APPROVED_PLATFORM_CHANGE_PROPOSAL
```

出现未裁决的硬冲突：

```text
R2_AUTHORITY_INSTALL_BLOCKED_DESIGN_CONFLICT
```

# Local content-safety evidence consumers

This implementation binds an independently received decision to exact bounded bytes. It does not classify arbitrary prose, images, speech or music. It does not alter world rules, seeds, mechanical AI authority, release gates, B002 or any of the eighteen INT011 stage obligations.

## Production entry

`tools/content_safety_consumers.py media|region|cross-region|build|rc --input-root DIR --execution UUID` and `tools/build_package.py --execution UUID` open only `/var/lib/rules-residue/content-safety`. Requests cannot choose a trust root, clock, reviewer or TEST_ONLY mode. Missing deployment configuration, current evidence or issued operation denies admission. `build_package()` including `validate_first=False`, alternate package roots and CLI `--skip-validation` uses the same boundary.

The deployment operator installs the fixed directory outside any checkout: private directory and SQLite database, a root-owned non-group/world-writable `operator.json`, the independent custody repository and separately durable `guard.json`. This is an OS protection for the existing operator role, not a new signing principal. Production configuration contains exact `authority`, `source`, `custody_repository` and `accepted_statements` (receipt SHA-256 to exact commit/tree/path/blob locator). The operator populates a locator only after actual independent report/manifest verification and root reception. Same-key signing or different identity strings alone never registers a locator. No consumer or CLI can bootstrap this file. Offline provisioning uses `ControlStore._initialize` in the trusted operator process; a missing protected configuration keeps even a fabricated database inert.

`source` fixes current clean Git commit/tree, an aggregate digest of evidence/control/consumer/builder code, the exact receipt schema and existing R2 red-line policy bytes. `authority` fixes namespace, checkpoint, revocation epoch and policy/consumer/schema revisions. Clock establishment, boot ID, maximum observed UTC, monotonic observation and checkpoint expiry are persisted. Receipts have conservative two-second time margins and at most one-hour validity. Reopening after source/configuration drift fails. The `reconcile` control command consumes only the protected operator configuration, serializes with commit transactions and requires the next revocation epoch for source/policy/schema/checkpoint or revoked-receipt changes. It cannot take a request-supplied clock or trust root; boot/clock reestablishment remains an offline trusted operator action. Never restore the SQLite database without its independently retained current guard: conflicting generations, time or epoch deny further admission.

The control writer issues an operation before any receipt is ingested. Receipt ingestion cannot issue one. The unique occurrence tuple and operation/phase keys reject duplicate effects; an identical receipt retry does not increase receipt sequence. Build INPUT and OUTPUT share the same operation and checkpoint. A received receipt increments only receipt sequence. Production evidence supplies the exact independent report and manifest bytes (hex encoded for transport) and locator; the root statement must bind their actual hashes, exact receipt bytes, distinct producer/reviewer task and run identities, decision, checkpoint and epoch. The fixed SSH public key verifies custody with process-local Git trust and replacement objects disabled. No private key is read by a consumer.

## Input closure and bounded formats

Every raw JSON file is part of the inventory, as are all referenced bytes. The root hash is SHA-256 of the frozen NUL-terminated inventory domain followed by canonical sorted records. Paths are bounded ASCII POSIX relative names; case aliases, traversal, missing/extra files, links, special files and unsupported modes reject. The source is opened by directory descriptors with no-follow on every component. Before/after inode, size, mode, timestamp and link-count checks surround bounded copies. Snapshot files are fsynced, read-only and accessed through retained descriptors. Source namespace and raw hashes are rechecked before commit; reference hashes/revisions must resolve through this closure.

Audio is the independent frozen `audio_intake`, not an extension to a Visual Order. The finite decoder supports only exact 44-byte RIFF/WAVE headers followed by PCM16 little-endian data, one/two channels, 44100/48000 Hz and at most 60 seconds. A present transcript is mandatory unless an independently accepted report explicitly covers the exact absence. No inference about untranscribed speech is made. Images retain the unchanged native Visual Order and Task Packet checks, with closed PNG RGB/RGBA8, non-interlaced, bounded dimensions, CRC/decompression and two-second decoder checks. Other chunk semantics/formats deny.

A region requires the native acceptance schema/helper, dossier, every V0–V6 report, exact revision and separate applicable Owner approval evidence. The accepted independent report must list each consumed subject with exact role, region, revision and file hash; standalone PASS strings never suffice. Cross-region consumes six current committed child admissions and all their original bytes, resolves every imported symbol to one export at the exact child revision and binds the combined adjacency. The child closure is resolved in its previously verified child namespace, rather than reinterpreted with another region's aliases.

Build INPUT authorizes local isolated computation. Full/default-root validation runs the original validator in a dedicated fixed-source clone whose package inputs are copied only from snapshot descriptors; alternate roots preserve original module validation. `_quarantine_encode` is the explicit internal structural encoder. It never installs a token or grants semantic authority. The three old package/module/adapter tests retain their original assertions using this encoder. The raw archive remains the 37-member `0.1-draft` format. Build OUTPUT separately binds whole archive bytes plus ordered member metadata and the package lock, and is required before commit. ZIP duplicate names, aliases, links, traversal, over-limit expansion and lock drift reject.

RC requires a current committed archive, a FORENSIC DAB with its entire referenced closure, current stage admissions and root evidence. It emits a local admission record only. Release remains `BLOCKED_BY_DESIGN`.

## Transactions and recovery

SQLite uses WAL, FULL synchronization, foreign keys and a 5000 ms busy timeout. BEGIN IMMEDIATE has at most three 50/100/200 ms retries. Versioned CAS changes ISSUED to PREPARED then COMMITTED, or denies by ABORTED. Exclusive per-operation locks prevent two processes computing one operation concurrently. PREPARED only permits local quarantined work. All output bytes and parent directories are fsynced; authority, time, source, input and complete phase evidence are rechecked in the commit transaction. The guard is durably advanced before the database commit: interruption between them produces a fail-closed conflict requiring operator reconciliation.

Build may stop PREPARED with `OUTPUT review required`; later execution revalidates inputs and reuses the saved archive after independently inspecting its exact member bytes. No new encoder invocation is needed. Other recovery revalidates the bounded input and recomputes local format/graph checks. A process crash leaves no consumable result until the database COMMITTED pointer exists. Committed replay returns the exact stored manifest and `replay=true` without reopening inputs, re-encoding or calling external services. Historical replay after revocation remains historical; every new downstream consumption invokes current authorization checks.

`ControlStore.create_test_only` and `exercise_test_only` explicitly mark mechanical fixtures without production authority. Production API/CLI rejects these stores. Fake approval labels in tests are not Owner decisions or semantic safety evidence. The finite, independently reviewed audio verification is separately bound to a real received statement when executed; it authorizes no other consumer's content.

`run_acceptance.py` reports structural/regression/determinism results and `content_safety_admission.status=NOT_CLAIMED`. Successful raw builds and unit tests never mean semantic ALLOW or closure of the eighteen stages. Independent implementation acceptance is still required.

# 05 — AI Agent Contract

## 1. AI 角色

- `ai_gm`：在 Campaign 的 Authority Contract 允许时提出场景推进、NPC 动作和规则工具调用；
- `ai_player`：仅控制被分配的角色并提出玩家动作；
- `human_gm_assistant`：只生成草稿、检索和建议，不自动提交主持裁定；
- `summary_agent`：只生成派生记忆，不具有规则权限。

AI 身份必须在参与者列表、UI、事件与导出中明确标记。

## 2. 不可越权

Agent 不得：

- 直接返回数据库或状态补丁；
- 自行生成、替换或隐藏骰子结果；
- 切换 Human GM / AI GM 主持模式；
- 读取其投影之外的秘密；
- 把推测写成 confirmed fact；
- 通过叙事宣告未被 Event 支持的状态变化；
- 调用 Game Package 未声明的工具。

## 3. 自然语言处理合同

Agent 将玩家文本转为 `StructuredAction`，必须显式给出：

- 行为目标；
- 动作类型；
- 目标对象；
- 采用的方法；
- 预期代价或资源选择；
- 需要澄清的歧义；
- 输入文本引用。

规则不明确时，Agent 应返回澄清或多个候选动作，而不是发明新规则。

## 4. 叙事合同

叙事输入只包含已提交 Event、参与者投影、公开规则解释和允许的风格信息。叙事输出不得展示完整内部推理、服务器秘密、未授权投影、系统提示或原始工具调试数据。

## 5. 上下文压缩

压缩只允许减少表达，不得改变事实状态。每条长期记忆必须带来源 Event ID、可见性、确认级别和摘要版本；失去来源的摘要不得进入 Agent 上下文。

# 03 — Design Principles

1. **规则本身就是谜题**：玩家必须能够通过观察、假设、验证、反例、例外和规则冲突逐步理解异常，而不是等待 GM 直接公布答案。
2. **规则必须可执行**：核心规则对象必须具有作用域、触发、条件、效果、例外与优先级；叙事不能成为唯一裁定机制。
3. **未知 ≠ 不存在**：世界真相、玩家假设、已确认知识和错误认知必须分别记录；AI 不得把猜测升级为事实。
4. **破解不等于无视**：玩家可遵守、利用、绕过、覆盖或破坏规则，但必须满足可验证条件并承担对应代价。
5. **开放世界必须持久**：地点、NPC、资源、规则状态和玩家造成的变化可重访、可保存，世界不随“副本结束”自动复原。
6. **规则可叠加且必须可判定**：多个规则域同时生效时，冲突通过声明的作用域与优先级解析，不能让 Agent 随机选择。
7. **规则可执行，叙事可生成**：规则与状态变化由确定性逻辑产生，AI 只解释意图和叙述已提交事实。
8. **失败改变局面而非停止游戏**：关键路径失败必须付出代价并继续推进；生存压力可以加剧，但不能靠无限重投推进。
9. **秘密是数据边界**：不依赖提示词要求模型“不要说”；先投影，再调用 Agent。
10. **AI 是显式参与者**：AI 身份、权限、工具和主持权在状态中可审计。
11. **官方与第三方同权**：第一方包不使用隐藏能力。
12. **状态优先于上下文**：存档与事件是事实来源，聊天与摘要只是派生信息。
13. **创作工具可往返**：图形编辑与 Lua/JSON 导出不能改变未编辑语义。
14. **可错过不等于可卡死**：真相碎片、奖励、支线可以失去；主流程必须有继续生存和探索的路径。
15. **长期真相延迟冻结**：世界来源、规则来源和归乡条件保持 GM-only 且由后续设计轮决定，不能在实现任务中被擅自补全。
16. **混合开发，单一验收权威**：不同模型可并行产出，但最终 PASS 只能基于 Codex 执行的仓库级验证与证据。
17. **生产最小暴露**：不加载 debug，不泄漏内部提示、服务器真相或不可见工具结果。

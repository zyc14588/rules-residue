# 00 — Project Charter

## 1. 项目定义

《规则残差》是与 TRPG_PLATFORM 分离、独立版本化、独立发布的第一方原创 TRPG。它既提供开箱可玩的原创内容，也作为平台通用游戏能力的 executable specification。

**机器标识**：`org.trpgplatform.rules-residue`  
**显示名称**：`规则残差`  
**英文显示名**：`Rules Residue`  
**当前阶段**：M0 初始化 Revision 1 / pre-alpha  
**当前版本**：`0.1.0-dev.1`

## 2. 冻结的产品定位

本项目是**无限流叠加规则怪谈的异世界开放世界跑团游戏**。

玩家角色被置于无法立即返回原世界的异世界。生存依赖于观察异常、识别规则、建立假设、验证规则、寻找例外与冲突、利用或破解规则，并在持续探索中拼合跨区域真相。长期目标同时存在四层：

1. **活着**：处理即时危险、资源、伤害、负荷和环境规则；
2. **破解规则**：把规则从未知威胁转化为可验证、可利用、可绕过或可破坏的知识；
3. **查清真相**：收集跨规则域相互印证的世界事实与元规则线索；
4. **回家**：发现并满足归乡条件，而非把“通关一个副本”默认等同于回家。

“异世界为何存在”“谁或什么制造规则”“无限流结构的最终来源”“真正归乡条件”在 M0 阶段曾明确不冻结；该历史状态现已 `SUPERSEDED_BY_R2`，当前 GM-only 真相以 `docs/authority/r2/` 与 `governance/r2/decisions.r2.yaml` 为准。

## 3. 开放世界定义

“开放世界”是权威状态属性，不是宣传语：

- 世界区域长期存在并可重访；
- 玩家路线不是固定关卡链；
- 规则域可以相邻、嵌套、重叠和发生迁移；
- 玩家行为会持久改变地点、NPC、资源、已知规则和威胁；
- 已确认规则知识必须能跨 Session 保存；
- 进入新规则域不能自动清除旧世界状态。

“无限流”提供不断变化的规则环境与跨域压力，但不得把世界降级为互不关联、打完即销毁的线性副本列表。

## 4. P0 成功定义

P0 成功不是“写出完整规则书”，而是用标准 Game Package 完成以下闭环：

```text
原创规则域与角色
  → 自由探索 / 玩家自然语言
  → AI/客户端生成结构化动作
  → Lua 计划动作
  → 宿主权威随机
  → Lua 解析并返回 Typed Effects
  → Go 权威事务提交 Event/State
  → 规则假设/已知事实/世界真相保持分层
  → 按参与者生成可见投影
  → AI 基于已提交事实叙事
  → Checkpoint / Resume / Replay
```

该闭环必须同时被 Tutorial Scenario 和 Golden Scenario 验证。

## 5. 所有权边界

本项目拥有游戏语义；平台拥有执行基础设施。平台不得理解“洞见”“负荷”“规则域”“规则假设”“规则残差”等游戏专有概念，只能理解通用的包、命令、事件、状态、可见性、事务和 Agent 调用合同。

## 6. 原创性

正式 Game Package 输入只能包含自主创作或具有明确书面授权的内容。M0 初始化不引入任何第三方游戏兼容层。

## 7. 混合开发

Game Package 采用 Codex / OpenCode / Grok 混合开发，但**治理权不分散**：Codex 负责创建任务计划与验收标准，并对返回产物执行最终验证；OpenCode 只执行脚本编码任务；Grok 只执行美术资产创作任务。任何工具都不得仅凭自己的自述将任务标记为最终 PASS。

## 8. 当前非承诺

- 本初始化包不是正式发行版；
- `0.1-draft` Host API 不是稳定接口；
- 具体骰制、完整职业/成长与 R2 deferred register 列出的细节尚未冻结；R2 已接受的世界与终局真相不在此列；
- 当前 Lua 代码是合同级最小参考实现，仍需在平台真实沙箱中集成认证；
- 当前无正式美术、音频或完整战役。

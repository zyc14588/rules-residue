# 视觉、音频、文本与地图表现

## 技术表现边界

首发使用纯2D：

- 2D场景与立绘；
- 2D区域/战斗地图；
- 图层光照、天气与异常；
- 2D骨骼或逐帧动画；
- 规则界面和关键动态演出。

不制作2.5D、3D自由探索或依赖三维视角的核心谜题。

## 视觉语法

正常世界低饱和且可信。异常按层级逐步破坏构图、空间、文本、倒影和运动逻辑。逻辑完全异常区必须提供显著警告。

关键道具保持同一因果核心：

- 1型：内折、收束、记录、稳定；
- 2型：外翻、展开、干涉、侵入。

Boss不同人格和维护职责必须拥有稳定视听语法。

## 文本多声部

六类风格是表现预设，不是机械类别：

1. 守则/手册/告示；
2. 公文/档案/媒体；
3. 私人叙事；
4. 礼数/商业话术；
5. 教义/经典互文；
6. 元层/戏仿/双声道。

每份文本内部拥有结构化来源、受众、版本、权限、可靠状态和功能标签，但玩家不可直接看到这些字段。

## 渐进式披露

玩家先见原始载体，再按需展开：

```text
可访问文本
→ 来源和物理属性
→ 版本差异
→ 玩家批注
→ 证据关系
→ 因果主张
→ 代价与终局用途
```

辅助层不得标记真假或真结局必需。

## 音频与可访问性

声音可以承载钟声、广播、方向、双声道与沉默线索，但必须提供等价视觉/字幕/振动/转录渠道。降低声光刺激不得泄露答案。

## 地图

主持人持完整权威地图。玩家只自动记录角色确认的信息；有测绘或空间技能者能提高侦察记录精度、识别不可能空间和版本差异。

## 内容生产

核心因果人工定义。生成模型只能在结构化约束中生成表现层。所有内容必须保持原创来源、版本和机械一致性记录。
